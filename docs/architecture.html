Irreversibility Budget for Process Groups

CSL3030 Operating Systems Lab · xv6-riscv · Problem 1 · Architecture and design guide (v1, draft for team review)
Our idea in one line. The kernel charges a process group for the damage it cannot undo, and it can make some actions undoable so that they cost less. The required token-bucket budget is the base. On top of it we close the loopholes a flat cost table leaves open: group escape, hidden destructive syscalls, cost that ignores size, starvation in BLOCK mode. We also add a kernel trash that turns an irreversible delete into a reversible one.

1. Big picture: where the budget sits

An agent decides on an action. A user program carries it out. The action reaches the kernel as a system call. The kernel is the last component that sees the action, and the only one that can refuse it. Our whole mechanism is one decision point, the budget gate, placed in syscall() before the real handler runs.

Figure 1. The full stack. Everything above the yellow gate can be tricked. The gate cannot be talked around because it runs in the kernel.

Why a group and not a process. A refused process can fork, and the child would start with a fresh allowance. So the budget belongs to the whole family. fork() copies gid, and exec() keeps it, because exec changes the program image but not the process.

2. Spec mode vs strict mode

The instructor keeps about 70% of the tests hidden, and they are written against the handout's behaviour. If our extensions change the counts (for example a size-dependent unlink cost), hidden tests that hand-calculate counts would fail. So every extension sits behind one runtime switch.

ModeBehaviourUsed for
SPEC (default at boot)Exactly the handout: flat cost table, any process may setgroup/setbudget, plain BLOCK/FAIL, unlink really deletes.Hidden tests, usertests, required graphs.
STRICTTurns on nested budgets, leak charging, size-proportional cost, fair queue, trash, and the circuit breaker. Each feature also has its own bit.Our attack demos, extension graphs, agent demo.
// kernel/budgetparam.h  — the ONE place where team parameters live
#define BP_NESTED     (1<<0)   // escape closure
#define BP_LEAKS      (1<<1)   // charge O_TRUNC, overwrite, unlink of dirs ...
#define BP_PROPORTION (1<<2)   // unlink cost grows with blocks freed
#define BP_FAIRQ      (1<<3)   // FIFO tickets in BLOCK mode
#define BP_TRASH      (1<<4)   // reversible delete
#define BP_BREAKER    (1<<5)   // freeze group after repeated refusals
int budget_policy = 0;         // 0 = SPEC mode. Changed only by root via budgetctl()

A new syscall budgetctl(flags) (callable only from group 0) flips the bits, so one kernel build runs every experiment.

3. Component 1: the group table CORE

The budget is shared, so it lives in a global table, not in struct proc. struct proc gets only int gid. There is one spinlock per entry, not one global lock: two groups on different CPUs never contend.

Figure 2. Many processes point at one shared group entry.
struct group {
  struct spinlock lock;
  int  in_use, parent;           // parent used only in STRICT/nested mode
  int  budget, max, refill, mode;// mode = BUDGET_BLOCK or BUDGET_FAIL
  uint last_refill;              // tick of last whole-period refill
  int  n_allowed, n_blocked, n_refused;   // for budgetstat
  uint next_ticket, now_serving; // fair queue (EXT)
  int  refusals_window;          // circuit breaker (STRETCH)
};

Syscalls. setgroup(gid) moves the caller into a group (children inherit it on fork). setbudget(gid, max, refill_per_100_ticks, mode) configures a group and fills it to max. Group 0 is the root: unlimited and never charged, so init and the shell keep working and usertests stays unaffected. Choosing gid 0 as unlimited is our decision. We document it, and the default cost path short-circuits when gid == 0.

4. Component 2: the cost model CORE + EXT

Each syscall gets a cost from syscall_cost(num, p). Some costs depend on the arguments (which file, who created it), so the function peeks at the arguments before the call runs. It only reads, it never changes anything.

The real numbers come from our assigned per-team cost table. They go into budgetparam.h and nowhere else.

int syscall_cost(int num, struct proc *p) {
  if (p->gid == 0) return 0;
  switch (num) {
  case SYS_unlink: return cost_unlink(p);           // peeks path, size if BP_PROPORTION
  case SYS_write:  return cost_write(p);            // peeks fd: console / own / other
  case SYS_exec:   return cost_exec(p);             // peeks path creator
  case SYS_open:   return (budget_policy & BP_LEAKS) ? cost_open_trunc(p) : 0;
  default:         return COST_DEFAULT[num];
  }
}
Why peeking is safe. Reading an fd or calling namei() has no side effects. Inside begin_op()/end_op() we look up the inode, read creator_gid and size, then iunlockput(). Nothing changes on disk. The peek is done before charge(), because charge may sleep and we must not sleep holding an inode lock.

5. Component 3: the syscall gate CORE

Figure 3. The gate. The charge sits before the real handler. Charging after the work would let a budget of 1 permit an unbounded delete.
// kernel/syscall.c
if (num > 0 && num < NELEM(syscalls) && syscalls[num]) {
  int cost = syscall_cost(num, p);
  if (cost > 0 && charge(p->gid, cost) < 0) {
    p->trapframe->a0 = -1;            // refused (FAIL) or killed while blocked
    return;
  }
  p->trapframe->a0 = syscalls[num]();
}

6. Component 4: refill and the token-bucket math CORE

We refill lazily: no timer work per group. Whenever someone touches a group, we compute how many whole 100-tick periods passed.

periods      = (now − last_refill) / 100          // uint subtraction: survives wraparound
budget       = min(max, budget + periods · refill)
last_refill += periods · 100                      // NOT = now; that throws the remainder away

Writing last_refill = now instead would lose up to 99 ticks on every refill, so the real rate drifts slow. The staircase in the graph would show it.

Reading ticks without a race. ticks is changed under tickslock by clockintr(). Inside refill() we take tickslock only to copy ticks into a local. Lock order is always g→lock then tickslock, never the reverse.

Expected curve (this is what we must see in the graph)

Let B = start budget, c = unlink cost, r = refill per 100 ticks. Completed deletions by tick t:

FAIL :  N(t) = ⌊B / c⌋                              (flat forever)
BLOCK:  N(t) = ⌊(B + r·⌊t/100⌋) / c⌋   (until the 200 files run out)

With B = 50, c = 10, r = 10: FAIL stops at 5. BLOCK gives 5 at once, then one more every 100 ticks.

Figure 4. Expected shape (illustrative, from the formula; the real graph comes from QEMU logs). A step every 100 ticks is the refill period.

7. Component 5: BLOCK, FAIL and the fair queue

CORE FAIL returns −1 at once. BLOCK sleeps on &ticks (which clockintr() already wakes every tick), then refills and re-checks in a while loop. It must be a loop: another process in the same group may wake first and take the refill.

EXT The starvation problem. In the plain design a cheap call always wins. Say group 2 has a write loop (cost 1) and a blocked unlink (cost 10). Every refill of 10 gets eaten one unit at a time by the writer before the unlink ever sees 10. The unlink can wait forever. We fix it with tickets.

Figure 5. Ticket lock idea applied to budget waiting.

STRETCH No thundering herd. With n blocked processes, the plain design does n wakeups per tick, almost all useless. Since refill is deterministic, the head can compute when it will be affordable: t* = last_refill + 100·⌈(cost − budget)/r⌉. It then sleeps on a per-group channel that clockintr() wakes only at t*. Metric: wakeups per successful charge, plain vs targeted.

"Write to a file created by your own group" needs to know who created the file, even after a reboot. So it goes into the on-disk inode.

The field is mirrored in the in-memory struct inode and copied in ilock()/iupdate(). ialloc() sets it to the caller's gid and always overwrites it on reuse, so a deleted and recreated file can't inherit an old owner. mkfs writes 0 (root) for files baked into fs.img, so /README and the binaries belong to root.

9. Component 7: nested budgets, closing the escape EXT

The hole in the plain spec. The handout closes the fork attack, but if any process may call setgroup(99) and setbudget(99, 1000, …), a runaway simply moves itself into a fresh, rich group. That is the fork bomb again, one syscall later.
Figure 7. Groups form a tree. A process can only move down into a new subgroup, never up or sideways.

Rules in STRICT mode.

  1. setbudget is only allowed on a group that is a strict descendant of the caller's group (root can configure anything).
  2. Creating a subgroup carves its max and refill out of the parent: the parent's remaining budget and refill go down by the same amount. When the subgroup dies (its last process exits), whatever is left returns to the parent.
  3. setgroup(g) is only allowed into a descendant of the current group.

Why this is enough. Total spend of any subtree per 100 ticks ≤ refill of its root. No sequence of fork, setgroup or setbudget can create budget out of nothing. We prove it in the report with one line of induction on tree depth, and show the escape attack succeeding in SPEC mode and failing in STRICT mode.

Why carve-out and not hierarchical charging. Charging every ancestor on every syscall needs several group locks at once (deadlock risk, slower). With carve-out each charge still touches exactly one group lock. Only group creation and exit touch two locks, always taken parent before child.

11. Component 9: kernel trash, the reversibility discount EXT

This is the part that makes the project about irreversibility and not only rate limiting. If the kernel can undo a delete, the delete isn't irreversible, so it should be cheap. The full price is paid when the undo becomes impossible.

Figure 8. State machine of a deleted file under BP_TRASH.

How it works in xv6. unlink under BP_TRASH does, inside one begin_op/end_op: dirlink(/.trash/<gid>, <inum>, ip), then removes the old directory entry. nlink stays 1, so no blocks are freed. A side table trash[NTRASH] = {gid, inum, original path, tick} records it. undelete(inum) reverses it. purge(gid) does the real unlink and charges the full price. Both directory updates touch few blocks and fit under MAXOPBLOCKS = 10.

Key property to state in the report. The total irreversible cost charged to a group equals the full-price cost of the files it actually destroyed. With the trash, a runaway agent that deletes 200 files only trashes them, and the user can restore everything. This is the demo.

12. Component 10: observability

CORE budgetstat calls getbudgetstat(gid, struct budgetinfo *out) (copyout) for each in-use group and prints:

0    root   -           -       -        -        -        -
2    BLOCK  23/50       10      27       14       0        0
3    FAIL   0/30        5       6        0        194      0

EXT Audit ring. A 256-entry kernel ring of (tick, gid, pid, syscall, cost, verdict). budgetstat -v dumps it. This gives the raw evidence for every graph.

STRETCH Circuit breaker. If a group gets more than N refusals inside W ticks, it is a runaway retry loop. The kernel freezes the group (every charge fails) and prints one line. Root can unfreeze.

18. Known limitations (to write honestly in the report)

  • Check-then-use gap. The cost is computed from a peek. Between the peek and the real handler, another process could swap the file (for example unlink + recreate with a different creator). We charge the peeked cost. A full fix would charge inside each handler at the point of the inode lock.
  • The cost table is a policy, not a measurement. "Irreversible" is our model. Console output can't be recalled, but we charge it per call, not per byte.
  • Disk-fill (L7) is not covered unless the block quota stretch is done.
  • Trash uses disk space until purge. The quota bounds it, and eviction is charged.
  • gid 0 is unlimited. Anything running as root is not budgeted. That is a deliberate choice so the system stays usable.
  • Fair queue adds head-of-line blocking (measured, not hidden).
  • No persistence of budgets across reboot. Group state lives in memory, only creator_gid is on disk.
